# AE350 内存系统验证合同

> 适用机器：`mega138k_ae350`。配置以机器 JSON 和所选硬件产物的导出为准。

此合同用于平台内存系统回归；准确镜像、性能 baseline 与验证范围见匹配验收报告。

CPU 内存系统使用 AE350 本地内存与 DDR 宽窄转换；DMAC 与视频 reader 的专属要求见各自合同。测试不改另一台机器的 current/baseline，Flash 写入须明确授权，冷启动和长时压力按具体任务选择。

## 验收标准

| 编号 | 要求 | 可检查的通过条件 |
| --- | --- | --- |
| M1 本地内存 | 使用硬核 ILM/DLM | 读取真实配置与使能状态；验证各自容量、CPU 读写/执行及故障恢复。DLM 承担工作数据、栈和诊断结果，ILM 承担关键代码；复制/清零、ECC 条件显式处理。启动固件通过官方Flash XIP执行，热代码段在启动时装入ILM |
| M2 burst 读适配 | 利用 256-bit UI 返回数据 | 捕获实际 HADDR/HTRANS/HBURST/HSIZE/HPROT；同一 32 B 块内合法的 4×64-bit 或 8×32-bit 读 burst 只发 1 条 UI 读命令。跨块、WRAP、BUSY、提前结束、错误和复位正确；不同独立 burst 不复用旧块，不对 MMIO 预取 |
| M3 写通路 | 避免每个窄 beat 都占用整个 DDR burst | 按硬核实际 write-back 事务设计聚合/宽窄转换，记录 byte-valid、mask、有效字节及 UI 命令数。明确提前应答、读转发、排空、超时与失败语义；不允许通过等待后续 beat 阻止主机完成当前 beat。部分写和尾块保持邻接字节 |
| M4 时钟 | 内存数据口与外设时钟独立建模 | CPU core、data AHB、peripheral AHB/APB、DDR UI、DDR CK 分列配置、约束与实测依据。数据口选择由合法频率、完整 STA 和实板决定，不随 BSRAM/外设限制盲目降频，不声称未经测试的理论上限 |
| M5 协议与 CDC | 效率优化不破坏正确性 | 真实异步 FIFO 联合仿真；地址/数据相位、burst 边界、背压、迟到响应隔离、错误后恢复、协调复位断言与独立域释放均有定向回归（不承诺任意单侧热复位透明恢复）。单 bit 同步，多 bit 握手快照；完整 STA 包括 setup/hold/最小脉宽，禁止用豁免掩盖同域故障 |
| M6 自举 | 只有一条加载协议 | 硬件校准→Flash XIP启动/本地内存POST→UART loader→DDR 程序；诊断载荷也走 UART，错误上传可重试，DDR 不可用时可恢复。JTAG 仅调试、身份核对和恢复 |
| M7 完整性 | 验证最终候选拟发布区间 | 容量/别名、所有 byte lane/掩码、全范围分块遍历、cache 维护和 DDR 执行；列明运行镜像/栈/参数等排除区。400 MHz 至少 10 次复位重新校准，记录类型/状态/时长；不将重配置称为冷启动 |
| M8 性能 | 能证明结构改善 | 同一工作集和 cache 条件与基线比较；读/写/copy/依赖加载各 3 次，记录 logical bytes、UI 命令数/字节、有效 mask 字节、周期及主机墙钟。核心频率未独立验证前只发布原始 cycles。短压力以主机单调时钟记录实际运行/暂停，不把整套载荷时长当压力时长；30 分钟要求已取消 |
| M9 交付与恢复 | 源码、产物、工具、证据对应 | mini 为唯一公开入口；配置进入内容寻址依赖；普通应用不依赖诊断载荷。在当前平台验证 loader 重入、错误上传重试、软件恢复及重配置启动，保存最终驻留身份。报告明确逐项状态及限制，归档真实 ROM/payload 依赖闭包 |

## 顺序与边界

先核对并启用 ILM/DLM，建立独立的数据口时钟配置和真实 burst 观察；再完成读宽窄转换，依据实测事务实现写通路并评估流水。最后冻结时钟/ABI/内存布局，完成全范围及恢复验收。每个候选保存独立回执，未通过不得覆盖基线。

跨独立请求可重复命中的缓存不是默认方案；若引入必须重新定义一致性。原子指令在现有 fabric 端口不受支持，能力表明确禁止，不能冒称支持。XIP 未实现；HDMI、DMAC 与共享仲裁的验证还须满足 [视频](video.md) 和 [DMA](dma.md) 合同。启动 ROM 保留硬核固定复位入口；ILM 内容通过显式装载获得，不假设 FPGA 配置会初始化硬核本地 RAM。

## HDMI 多模式的跨域流水线

运行时视频候选在 CPU 请求与响应异步 FIFO 的读端各增加两个并行寄存槽，
将 Gray 指针判断与宽数据选择/寄存器使能分开。底层 FIFO 仍为两项，额外寄存槽
持有已经弹出的事务，直到消费者明确退休。UI idle 同时检查寄存槽和底层 FIFO，
不把尚未进入寄存槽的新请求报告为空闲。

首次穿越每个 FIFO 增加一个接收域寄存周期；突发内的读行复用、写合并、
事务顺序和超时隔离语义保持。未提交给 DDR 的请求可以等待，已经接受的无标签读取
仍须等真实返回后才释放所有权。预读地址的相等/同线判断与预读地址捕获并行寄存，
在后续 WBUF/ADDRESS 状态使用，不增加新的 AHB 接受状态。

这些改动通过主机协议回归，不代表重新完成了本页历史实板测量；实际性能和稳定性
须关联新 gateware 的时序及板测回执。
