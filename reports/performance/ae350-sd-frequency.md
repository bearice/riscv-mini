# AE350 SD 10/25/50 MHz 对照

2026-10-25，当前卡已通过 **50 MHz、4-bit High Speed** 的只读实板测试。大块 API 吞吐约 **3.66 MiB/s（3.84 MB/s）**。25→50 MHz 的中位数提升约 0.3%，收益已趋于饱和；具体卡端等待、DMAC、缓存维护与 bounce copy 的时间占比尚未拆分。

| API 调用大小 | 10 MHz MiB/s | 25 MHz MiB/s | 50 MHz MiB/s |
| --- | ---: | ---: | ---: |
| 512 B | 1.267 | 1.395 | 1.395 |
| 4 KiB | 2.862 | 3.654 | 3.665 |
| 64 KiB | 2.864 | 3.657 | 3.669 |

同一位流、同卡、LBA 2048 起顺序读取相同 1 MiB，每项三轮，CPU I/D cache 均开启。驱动内部每条命令最多 4 KiB，64 KiB API 调用继续拆分。三种频率共 27 样本全部通过基准 CRC32 `1201fe31`、guard 和错误/停止检查。基准来自此前 10 MHz 对同卡同区间的重复读，不是独立主机卡镜像。

吞吐采用 64-bit 周期计数与 800 MHz CPU 时钟计算。此前长窗口主机墙钟核对约 799.7 MHz，与相同 CPU PLL 配置一致。UART START/END 墙钟也完整保留，但短窗口受到 USB/UART 缓冲和主机调度影响，不能用它解释 25→50 MHz 的小幅差异。计时包含 SD 命令、硬 DMAC、缓存同步及 bounce copy；初始化、CMD6 切换、CRC 和 UART 输出在周期计时区外。

原控制器在 80 MHz fabric 域分频，最高只能输出 40 MHz。新候选将 SD 置于现有 100 MHz mem 域，sys 保持 80 MHz；APB/AHB 用保留事务的异步 FIFO 跨域，ACK 用事件同步，sys 端抑制确认返回延迟期间的重复请求。SD 命令增加两项缓冲；数据 FIFO 每方向为 16 个寄存器字，避开 100 MHz 下块 RAM 的最小脉宽限制。

超过 25 MHz 前，BSP 用 CMD6 查询 High Speed 支持，再切换并核对功能选择结果，之后才改分频到 50 MHz。50 MHz 完成记录的返回状态无错误。完整 PnR setup/hold=0/0、最小脉宽裕量 +0.037 ns。前两次未通过的 setup/最小脉宽候选未用于板测，回执保留。

准确位流/软件身份、构建回执、原始周期和 UART 墙钟见 [JSON](ae350-sd-frequency.json)。位流 `55ef9313e934`；10/25/50 MHz 载荷分别为 `493769fc5d3c` / `8fe2ad566e46` / `18ab3712dfb1`。各域频率与旧 10 MHz 基准实现不同，因此提频比较以本表同位流三组为准；旧 80 MHz 源域结果保留于 [先前测速](ae350-sd-read.md)。

通过范围为当前卡的短时只读一致性和应用 API 吞吐，不包含 SD 写入、其他卡、独立物理时钟测量或音视频/SD 长时间组合压力。主机/RTL 检查覆盖真实 CMD0/CMD8 位序与 CRC7、异步 AHB 错误/数据相位、APB 单次提交、ACK 事件/请求抑制及寄存器 FIFO 满空/回卷/复位。

结束时 SD 请求门关闭、DMAC 排空，CPU 停留于测速完成后的 WFI。只编程 SRAM，不写卡/Flash、不改 current；FTDI JTAG 驱动绑定已恢复。
